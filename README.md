# Котик — школа спокойной силы

Первая рабочая версия, 0.1.0. Дата: 14 ноября 2026 года.

Учебный сайт на Astro: вики, практика, блог, задания проектов, маршрут и сведения о проекте. Русский, английский и чешский языки. Светлая, тёмная и системная темы.

## Состав версии

- 12 вводных занятий в каждом языке: 36 учебных страниц.
- 12 отдельных заданий в каждом языке: 36 страниц практики.
- 3 редакционные статьи в каждом языке: 9 публикаций.
- Главная, каталоги, поиск, тематические подборки, маршрут, проекты и описание проекта.
- Всего 127 статических HTML-страниц, включая корневую страницу выбора/перехода.
- Собственная векторная иллюстрация и знак Котика. Внешние шрифты, счётчики и сервисы комментариев не подключены.

Статьи блога — редакционные примеры, а не записи о событиях жизни Котика. Проекты — задания для будущих работ. Четыре направления пока содержат сообщение о подготовке материалов и связанные занятия базового курса. Английские и чешские тексты требуют языковой редакторской проверки перед использованием как образцовых учебных переводов.

## Запуск на компьютере

Требуется Node.js 24 и npm. Распаковать архив и открыть терминал в каталоге `kotik-school`:

```bash
npm ci
npm run dev
```

Открыть адрес, который покажет Astro, затем `/ru/`, `/en/` или `/cs/`. Для остановки нажать Ctrl+C. Для работы с черновиками использовать отдельную локальную ветку; личные заметки хранить вне публичного репозитория.

## Сборка и проверка

```bash
npm run build
npm run check:links
npm run preview
```

Проверка ссылок контролирует страницы, локальные ресурсы, языки, якоря и отсутствие ссылок вне базового пути. Это не заменяет визуальную проверку и проверку интерактивных элементов в браузере.

Включён каталог `dist` со сборкой для корня сайта. Исходники являются основной версией: при изменениях сборку необходимо повторить. Готовый `dist` не требуется сохранять в репозитории.

## Публикация на GitHub Pages

1. В аккаунте взрослого создать репозиторий, например `kotik`. Для бесплатного GitHub Pages обычно используется публичный репозиторий. Не добавлять при создании README, чтобы не создавать начальный конфликт.
2. Скопировать исходные файлы из архива в рабочую копию репозитория. Обязательно сохранить каталог `.github`.
3. Отправить файлы в ветку `main` через Git или графический клиент. Не отправлять `node_modules`, `.astro`, `dist`, пароли и личные записи.
4. Открыть Settings → Pages → Build and deployment → Source → GitHub Actions.
5. Открыть Actions и при необходимости вручную запустить workflow `Publish Kotik`.
6. Дождаться завершения build и deploy. Точный адрес появится в настройках Pages и результате deployment.

Workflow автоматически получает домен и базовый путь из `actions/configure-pages`. Для репозитория `kotik` в аккаунте `alsibir` ожидаемый адрес — `https://alsibir.github.io/kotik/`. Репозиторий и публичная публикация автоматически этой поставкой не создаются.

Проверка сборки для подпапки на Linux:

```bash
BASE_PATH=/kotik/ SITE_URL=https://alsibir.github.io npm run build
npm run check:links
```

После такой проверки для обычного локального предварительного просмотра снова выполнить `npm run build` без дополнительных переменных.

## Редактирование занятия

Каждая статья находится в отдельном Markdown-файле. В начале между разделителями `---` расположен объект JSON, допустимый как YAML front matter. Сохранять кавычки и запятые. Далее расположены обязательные разделы:

- `## body` — объяснение;
- `## example` — пример;
- `## caution` — типичная ошибка или ограничение;
- `## task` — задание;
- `## criteria` — критерии проверки;
- `## reflection` — вопросы для обсуждения.

Внутри разделов поддерживаются абзацы, списки, выделение и ссылки Markdown. Названия служебных разделов не переводятся: посетитель видит локализованные заголовки интерфейса. Не добавлять разделитель `---` в текст: он зарезервирован загрузчиком для метаданных.

Задание на странице практики берётся из того же файла: редактировать его второй раз не требуется. Нумерация `number` задаёт порядок в маршруте. Для сохранения переводов использовать одинаковые `id` и имена файлов во всех языках. В первой версии каждая публикуемая статья должна иметь все три языковые версии.

Добавление занятия: скопировать соседний файл в трёх языковых каталогах, задать уникальный `id`, очередной `number`, тему `topic` и время `time`, затем заполнить все разделы. Значение `topic` — от 0 до 6 в порядке направлений из интерфейса. После добавления выполнить сборку и проверку ссылок. Текущий заголовок маршрута рассчитан на 12 недель: при расширении программы обновить его в `ui.ts`.

Публикация блога: метаданные `id`, `title`, `tag`, `intro`, `related`, затем свободный Markdown-текст. Поле `related` содержит идентификатор связанного занятия. Пока весь блог обозначен как редакционные примеры; перед добавлением настоящих авторских записей внедрить отдельный признак авторства и статуса (см. ROADMAP).

## Содержание и редактура

Материалы представляют вводный авторский курс, а не клинические рекомендации или замену очных занятий. Упражнения строятся на вымышленных ситуациях. Чувства отделяются от оценок, просьбы допускают отказ, а безопасность важнее продолжения конфликта.

Список чтения пока общий: Розенберг, Аристотель, Фишер/Юри/Паттон. Следующая редакционная задача — подобрать конкретные издания, разделы и источники для каждой статьи. Не выдавать этот общий список за постраничные ссылки или за подтверждение каждого авторского примера.

## Проверка перед открытой публикацией

Проверить главную, статью, практику, блог и поиск на телефоне и компьютере; переключить язык на внутренней странице; проверить обе темы и системный режим; выполнить поиск с чешскими диакритическими знаками; проверить печать статьи. Убедиться, что нет настоящих имён других детей, адресов, школы, расписания, паролей и личных разговоров.

В текущем сеансе автоматическая сборка и проверка ссылок выполнены. Браузерная визуальная проверка не завершена: управляемый сервер предварительного просмотра не запустился.
